## 🚀 Активные открытые проекты (Open Source)

```
+--------------------------------------------------------------------------+

+--------------------------------------------------------------------------+
|  wire-sieve   [C / XDP]                                                  |
|  Высокоскоростной L4-диспетчер пакетов без сохранения состояния,        |
|  работающий на уровне драйвера NIC (до 14.8M pps на ядро 10GbE).         |
+--------------------------------------------------------------------------+
|  nanotrace    [Go / Rust / libbpf]                                       |
|  Легковесная консольная утилита для анализа хвостовой задержки системных |
|  вызовов Linux с субмикросекундными гистограммами в терминале.           |
+--------------------------------------------------------------------------+
```

### 1. `flow-kprobe`
- **Архитектура**: Перехватывает выполнение критических функций ядра (`tcp_v4_connect`, `tcp_set_state`, `tcp_close`) с использованием современной технологии CO-RE (`Compile Once - Run Everywhere`) eBPF.
- **Особенности**: Непрерывная передача событий кольцевого буфера в пространство пользователя без задержек на переключение контекста.
- **Производительность**: При нагрузке в 100 000 запр/с утилизация процессора не превышает `0.8%` на стандартном 8-ядерном сервере.

### 2. `wire-sieve`
- **Архитектура**: Обходит стандартный сетевой стек ядра Linux через нативный режим XDP (`XDP_TX` / `XDP_PASS`), мгновенно отбрасывая аномальный трафик и направляя валидные пакеты на проводной скорости.
- **Принципы**: Механическое сочувствие к оборудованию (Mechanical Sympathy), пулы памяти без динамических аллокаций, выравнивание структур метаданных по строкам кэша.

### 3. `nanotrace`
- **Архитектура**: Подключается к точкам трассировки `sys_enter` и `sys_exit`, измеряя фактическую длительность системных вызовов для потоков дискового и сетевого ввода-вывода.
- **Интерфейс**: Формирует распределения перцентилей в ASCII (`p50`, `p95`, `p99`, `p99.9`) прямо в терминале без внешних веб-зависимостей.

## 📊 Инженерные принципы и философия разработки

1. **Механическое сочувствие к «железу» прежде всего**: Программы выполняются на физическом кремнии. Выравнивание по строкам кэша, дружелюбность к предсказателям переходов и локальность NUMA важнее умозрительных абстракций.
2. **Явное лучше неявного**: Никакой «магии» в коде. Понятная обработка ошибок, строгая семантика владения памятью и минимум косвенной адресации во время выполнения.
3. **Наблюдаемость закладывается изначально**: Система, внутреннее состояние которой невозможно безопасно исследовать под пиковой нагрузкой, считается незавершенной.
4. **Data-Oriented Design**: Предпочтение непрерывным плоским массивам в памяти и векторизованным операциям перед глубокими иерархиями объектов.
