# هيوجون جو (Hyojun Jo / 조효준)

> **مهندس برمجيات نظم** — متخصص في قابلية مراقبة نواة لينكس (Kernel Observability)، ومعالجة حزم الشبكة فائقة الإنتاجية، والبنية التحتية الشبكية ذات زمن الانتقال المنخفض للغاية.

أقوم بتصميم وتحسين البرمجيات منخفضة المستوى حيث يُحدث كل ميكروثانية (μs) فارقاً جوهرياً. تتركز أبحاثي وتطويراتي حول قياس وتتبع نواة لينكس عبر تقنية eBPF، ومسارات الشبكة عالية السرعة المدعومة بـ XDP، وهياكل البيانات ذات الكفاءة العالية في استخدام الذاكرة، وبناء أنظمة القياس عن بُعد (Telemetry) الدقيقة للأنظمة الموزعة قيد الإنتاج.

- 📍 الموقع: سيول، كوريا الجنوبية (UTC+9)
- 💼 المجالات الأساسية: الأنظمة الفرعية لنواة لينكس، eBPF/XDP، وهندسة أداء الشبكات
- 💬 مجالات النقاش: موضع التخزين المؤقت (Cache Locality)، مخازن المقابس دون نسخ (Zero-Copy Socket Buffers)، بنيات المخزن الدائري (Ring Buffers)، خصائص وسلوك مدقق eBPF، وعمليات الإدخال/الإخراج عبر الذاكرة (mmap)

## 🚀 مشاريع مفتوحة المصدر نشطة

```
+--------------------------------------------------------------------------+
|  flow-kprobe  [Rust / C / eBPF]                                          |
|  محرك تتبع نواة لينكس بدون أي حمل إضافي (Zero-Overhead) لمراقبة دورة     |
|  حياة مقابس TCP وتحديد زمن انتقال الحزم بدقة الميكروثانية.              |
+--------------------------------------------------------------------------+
|  wire-sieve   [C / XDP]                                                  |
|  موزع حزم من المستوى الرابع (L4) بدون حالة يعمل في طبقة مشغل بطاقة      |
|  الشبكة، قادر على معالجة 14.8 مليون حزمة في الثانية لكل نواة 10GbE.     |
+--------------------------------------------------------------------------+
|  nanotrace    [Go / Rust / libbpf]                                       |
|  أداة طرفية (CLI) خفيفة لفحص زمن الاستجابة الأقصى (Tail Latency) لنداءات  |
|  نظام لينكس مع مدرجات تكرارية بصرية مباشرة في سطر الأوامر.              |
+--------------------------------------------------------------------------+
```

### 1. `flow-kprobe`
- **البنية الأساسية**: يرتبط بالدوال الحيوية لنواة لينكس مثل `tcp_v4_connect` و `tcp_set_state` و `tcp_close` باستخدام تقنية CO-RE الحديثة (`Compile Once - Run Everywhere`) في eBPF.
- **الميزة الرئيسية**: بث أحداث المخزن الدائري (Ring Buffer) إلى مساحة المستخدم بأدنى زمن تأخير وبدون أعباء تبديل السياق (Context Switching).
- **الاختبار القياسي**: تحت حمل اختبار اصطناعي يبلغ 100,000 طلب/ثانية، يظل استهلاك المعالج أقل من `0.8%` على خادم قياسي بـ 8 أنوية.

### 2. `wire-sieve`
- **البنية الأساسية**: يتجاوز مكدس شبكة لينكس القياسي عبر وضع XDP الأصلي (`XDP_TX` / `XDP_PASS`) لإسقاط الحزم المشبوهة فور دخولها بطاقة الشبكة وتوجيه الحزم الصالحة بسرعة السلك.
- **فلسفة التصميم**: التوافق الميكانيكي الدقيق مع العتاد (Mechanical Sympathy)، تجمعات ذاكرة بدون تخصيص ديناميكي، ومحاذاة بيانات الحزم مع أسطر التخزين المؤقت (Cache-Lines).

### 3. `nanotrace`
- **البنية الأساسية**: يتصل بنقاط التتبع `sys_enter` و `sys_exit` لقياس المدة الزمنية الحقيقية لنداءات النظام عبر خيوط إدخال/إخراج التخزين والشبكة.
- **المخرجات**: عرض رسوم بيانية مئوية باستخدام محارف ASCII (`p50`, `p95`, `p99`, `p99.9`) داخل الطرفية مباشرة دون الحاجة لأي واجهات ويب خارجية.

## 📊 مبادئ الهندسة وفلسفة كتابة الكود

1. **التوافق الميكانيكي مع العتاد أولاً**: البرمجيات تعمل على أجهزة فيزيائية حقيقية. محاذاة أسطر الذاكرة، وملائمة متنبئات التفرع، وموضعية عقد NUMA تحظى بالأولوية على التجريدات النظرية.
2. **الوضوح الصريح يتفوق على الضمني**: لا مجال للأكواد السحرية. معالجة صريحة للأخطاء، دلالات ملكية صارمة للذاكرة، وتقليل التوجيه غير المباشر في وقت التشغيل.
3. **المراقبة ليست فكرة لاحقة**: أي نظام لا يمكن فحصه وتحليله في بيئة الإنتاج الحقيقية دون التأثير على الأداء هو نظام غير مكتمل.
4. **التصميم الموجه للبيانات (Data-Oriented Design)**: التركيز على مصفوفات الذاكرة المتصلة والعمليات الموجهة (Vectorized) بدلاً من الهياكل الكائنية المتشعبة.
