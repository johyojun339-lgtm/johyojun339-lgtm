## 🚀 正在进行的开源项目

```
+--------------------------------------------------------------------------+
|  flow-kprobe  [Rust / C / eBPF]                                          |
|  零开销 Linux 内核探针引擎，用于追踪 TCP 套接字完整生命周期及微秒级数据包 |
|  延迟归因分析。                                                          |
+--------------------------------------------------------------------------+
|  wire-sieve   [C / XDP]                                                  |
|  直接在网卡驱动层执行的高吞吐 L4 无状态数据包分发器，单 10GbE 核心可达到  |
|  每秒 1,480 万数据包（14.8M pps）线速吞吐。                             |
+--------------------------------------------------------------------------+
|  nanotrace    [Go / Rust / libbpf]                                       |
|  轻量级 CLI 终端实用工具，利用亚微秒直方图精细化呈现 Linux 系统调用的长尾   |
|  延迟（Tail Latency）。                                                  |
+--------------------------------------------------------------------------+
```

### 1. `flow-kprobe`
- **核心架构**: 采用现代化 CO-RE（`Compile Once - Run Everywhere`）eBPF 技术，无侵入式挂载至 `tcp_v4_connect`、`tcp_set_state` 和 `tcp_close` 等关键内核函数。
- **关键特性**: 无需上下文切换即可将低延迟环形缓冲区事件持续流式传输至用户空间。
- **基准测试**: 在 10 万次/秒（100k req/s）的压测负载下，标准 8 核主机 CPU 占用率始终保持在 `0.8%` 以下。

### 2. `wire-sieve`
- **核心架构**: 利用 XDP 原生模式（`XDP_TX` / `XDP_PASS`）尽早绕过传统 Linux 网络协议栈，在物理网卡入口直接丢弃异常流量并线速重路由合规报文。
- **设计哲学**: 极致契合硬件机制（Mechanical Sympathy）、零内存分配池（Zero-Allocation）、缓存行对齐的报文元数据结构。

### 3. `nanotrace`
- **核心架构**: 动态附加到 `sys_enter` 与 `sys_exit` 跟踪点，精准测量存储与网络工作线程的系统调用实际消耗时长。
- **呈现方式**: 无需外部 Web 服务依赖，直接在终端内渲染纯 ASCII 分位数梯级（`p50`, `p95`, `p99`, `p99.9`）性能图表。

## 📊 工程原则与代码美学

1. **硬件机制共情（Mechanical Sympathy）至上**: 软件终究运行在物理硬件之上。缓存行对齐、分支预测器亲和力与 NUMA 节点局部性优先于纸面上的理论抽象。
2. **显式表达胜于隐式黑盒**: 杜绝魔法代码。追求清晰确切的错误返回值、严格的内存所有权语义，以及运行时最少化间接寻址。
3. **可观测性绝非事后补充**: 如果一个系统在高负载生产环境中无法做到零性能损耗的深度透视，它便是不完整的。
4. **面向数据设计（Data-Oriented Design）**: 优先选用扁平、连续的内存数组与向量化操作，替代深层复杂的面向对象继承层级。
